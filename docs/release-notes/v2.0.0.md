# SimpleWeatherClient 2.0.0

Adds One Call API 4.0 support while preserving existing One Call 3.0 and free-endpoint access. Existing weather-query methods and result properties remain available; the serializer-dependent model constructors are replaced with FromJson factories.

- Select `Automatic`, `OneCall3`, `OneCall4` or `Free` independently for each `WeatherController`, using the same account key where it has access. Explicit selections never silently switch services. Access denial identifies the selected service without exposing the key.
- Automatic selection prefers 3.0, then 4.0, then free, advancing only when access is denied. Existing 3.0 subscribers retain their service; no account migration or subscription change is performed.
- Use `GetWeatherSnapshotAsync` for current conditions and forecasts together. The 3.0 route uses one request. Set `includeHourly: false` for daily-only applications to avoid unused hourly pages: 4.0 normally needs two successful requests instead of five.
- Read paginated 4.0 forecasts up to eight daily and 48 hourly records, preserve requested units, and use HTTPS even when the service supplies HTTP continuation links.

An enabled OpenWeather subscription is still required for the selected One Call service. The library does not enforce an account quota or schedule polling. Automatic probes, geocoding, pagination, other applications and account terms affect usage; see [request counts](../library.md#request-counts-and-polling).

The library continues to target .NET Framework 4.7.2 and .NET 10. This release covers existing current/daily/hourly models, not the complete 4.0 history, long-range, minutely or alert-detail APIs.

Newtonsoft.Json has been removed from the library. See the [2.0 migration guide](../migration-v2.md) for the replacement fragment factories, changed JSON exceptions and net472 deployment dependencies.

The unused log4net dependency has also been removed; SimpleWeather contains no logging calls.

The console sample uses a combined current/daily snapshot. The widget requests daily forecasts without unused hourly pages and displays up to seven available days. The desktop application continues to request current conditions only. All three consume the same updated library.
